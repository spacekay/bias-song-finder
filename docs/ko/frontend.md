## 라우팅 구조

Next.js App Router를 활용한 아티스트 기반 동적 라우팅. 각 아티스트는 고유 색상이 동적으로 적용된 브랜디드 랜딩 페이지를 보유합니다. 라우트는 랜딩 페이지, 퀴즈 플로우, 결과 표시를 포함합니다.

공유 라우트 컴포넌트는 아티스트 설정에서 테마·내비게이션·메타데이터를 가져옵니다. 공개 여부와 백엔드 이용 가능 여부는 별도로 관리하여 준비 중인 설정이 자동으로 접근·검색 노출되지 않도록 합니다. 랜딩 페이지는 서버에서 이용 가능 여부를 불러오며, 알 수 없거나 비공개인 아티스트 경로는 404를 반환합니다.

---

## 결과 경험

매칭 결과는 해당 곡과 관련 곡 추천을 함께 보여줍니다. 매칭 실패·질문 소진 응답에도 추천을 포함하며, 질문이 소진되면 마지막 질문을 다시 열거나 매칭 실패 결과로 진행할 수 있습니다.

공유 결과는 저장된 언어 상태의 복원이 끝난 뒤 클라이언트에서 동일 출처 API 라우트를 통해 불러옵니다. 경계에서 언어 쿼리 값을 검증하고 잘못된 이전 형식의 링크를 정규화합니다. 퀴즈 상태가 만료되어도 결과는 조회할 수 있지만, 만료된 세션의 답변 이력은 제공하지 않습니다.

## 배포

[OpenNext](https://opennext.js.org/) 어댑터를 통한 **Cloudflare Workers** 배포

- 개발 및 프로덕션 워커 분리
- CORS 이슈 방지를 위해 프론트엔드 라우트를 통한 백엔드 API 프록시

---

## 요청 안정성

브라우저 API 클라이언트는 일시적 실패에 한해 재시도 가능한 조회 요청을 제한된 지연으로 재시도합니다. 변경 요청은 기본적으로 재시도하지 않습니다. 브라우저·Worker의 fetch 래퍼는 시간 초과 시 요청을 중단하고 타이머·취소 리스너를 정리합니다. 백엔드의 충돌 감지와 결과 생성 멱등성을 함께 고려한 구성입니다.

## 반응형 UI & 접근성

공유 아티스트 화면에 반응형 레이아웃, 키보드 조작, ARIA 라벨을 적용합니다. 필요한 Zustand 필드만 구독하여 불필요한 렌더링을 줄이고, 결과 조회와 세션 복구에는 로딩·에러 상태를 제공합니다.

---

## 테스트 & 품질

Jest + React Testing Library 기반의 단위 테스트로 hooks, 컴포넌트, API 클라이언트를 검증합니다. CI에서는 커버리지 기준, lint, 타입 검사, 빌드 검사를 수행합니다. 수동 검증은 전체 퀴즈 플로우, 접근성, 크로스 브라우저 동작을 대상으로 합니다.

## 주요 기능

- **공유하기**: 결과 확인 후 링크 복사 또는 X/Twitter 공유. 세션 만료 후에도 영속적 fallback 메커니즘을 통해 결과 접근 가능
- **성능 개선 작업**: 클라이언트 경계와 상태 구독 범위를 축소
- **운영 가시성**: 백엔드 요청 결과·지연 이벤트는 원시 세션 URL 대신 작업명을 사용하고, 정제된 CSP 보고로 정책 위반 진단
- **보안**: API 시크릿을 서버 사이드(Cloudflare Worker 환경)에 보관, 외부 입력에 대한 경계 검증, 엄격한 CSP / HSTS / Permissions-Policy 응답 헤더 적용
