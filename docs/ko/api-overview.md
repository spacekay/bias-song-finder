# API 개요

## 설계 철학

API는 **Stateless session flow**를 중심으로 설계되었습니다 — 사용자 로그인이 필요하지 않습니다. 세션 키가 사용자 식별자이자 퀴즈 상태 포인터 역할을 합니다.

모든 퀴즈 상태는 세션 키를 기준으로 외부에 저장됩니다. 백엔드 자체에 인메모리 상태가 없으므로 수평 확장이 가능합니다.

---

## 세션 생애 주기

- 세션 생성 시 고유한 세션 키 발급
- 퀴즈 진행 중 모든 요청에 세션 키 사용
- 설정 가능한 TTL과 명시적 연장 지원
- 만료된 세션 요청에 대해 적절한 에러 상태 반환

---

## 퀴즈 흐름

퀴즈는 세션 기반의 대화형 패턴을 따릅니다:

1. **세션 생성** — 아티스트의 전체 카탈로그에서 후보곡 풀 초기화
2. **질문 조회** — 백엔드가 가장 효과적으로 후보를 구분할 수 있는 다음 질문을 동적으로 선택
3. **답변 제출** — 사용자의 답변을 기반으로 후보곡 풀 필터링
4. **결과** — 퀴즈는 항상 결과 페이지로 귀결: 후보가 한 곡으로 좁혀지면 매칭된 곡, 후보가 사라지거나 모든 질문이 소진되면 유사도 엔진으로 산출한 가까운 곡들이 결과로 반환됩니다

"건너뛰기" (모르겠어요)가 항상 제공되며 — 후보곡을 필터링하지 않으므로 부분적인 지식만으로도 퀴즈 진행 가능

### Skipped Question Enrichment

매칭에 성공해 곡이 결정되면, 사용자가 건너뛴 질문에 대해서도 최종 곡의 실제 값을 결과 페이로드에 채워서 응답합니다. "건너뛴 질문의 답이 무엇이었는지"를 사용자에게 보여줄 수 있습니다.

### 동적 질문 전략

질문 선택 알고리즘은 현재 후보곡 풀 크기에 따라 전략을 조정합니다. 넓은 범위의 필터링 질문에서 시작하여 후보가 줄어들수록 타겟팅된 차별화로 전환됩니다. 후보가 충분히 적어지면 사용자가 남은 곡 중에서 직접 선택할 수 있습니다.

### Similarity Fallback

막다른 길을 만들지 않도록 answer·result 응답은 동일한 형태를 공유합니다: 메인 결과에 더해 가중 유사도 엔진이 산출한 가까운 곡 추천이 함께 포함됩니다. 프론트엔드는 no-match, 질문 소진, 매칭 성공 시나리오를 하나의 일관된 경로로 렌더링할 수 있습니다.

---

## 응답 형식

- 성공 응답은 표준 HTTP 성공 코드와 함께 데이터를 직접 반환
- 에러 응답은 에러 코드와 메시지를 포함한 구조화된 에러 객체 반환

---

## 보안 모델

- 프론트엔드가 백엔드에 인증하여 단기 JWT 발급
- 프론트엔드의 모든 요청에 JWT 첨부
- 퀴즈 세션 엔드포인트는 세션 키만으로 충분한 인증
- 세션 단위 분산 rate limiting으로 남용 방지

---

## 멀티테넌시

각 아티스트 그룹은 자체 데이터베이스 스키마를 가진 별도의 테넌트입니다. 테넌트 라우팅은 세션 컨텍스트에서 투명하게 해석됩니다 — API 소비자 관점에서는 모든 엔드포인트가 동일하게 보입니다.
