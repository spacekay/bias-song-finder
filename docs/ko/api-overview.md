# API 개요

## 설계 철학

퀴즈는 사용자 계정 없이 진행합니다. 세션 키로 Redis에 저장된 진행 상태를 식별하고, PostgreSQL에는 결과와 세션-테넌트 매핑을 남겨 세션 만료 후에도 공유할 수 있게 합니다. 애플리케이션 인스턴스는 퀴즈의 기준 상태를 메모리에 보관하지 않습니다.

브라우저 요청은 동일 출처의 Next.js API 라우트를 거칩니다. 이 라우트가 서버에서 백엔드 공유 시크릿을 첨부하며, 브라우저에는 전달하지 않습니다.

---

## 세션 생애 주기

- 세션 생성 시 선택한 아티스트의 후보곡 풀 초기화
- 이후 퀴즈 요청에 세션 키 사용
- 설정 가능한 TTL과 명시적 연장 지원
- 일반 상태 갱신은 TTL을 새로 부여하지 않고 남은 시간을 보존
- 만료된 퀴즈 상태는 `410 Gone`을 반환하지만 영속 결과 조회는 계속 제공

### 동시 갱신

세션 변경은 저장 전에 버전을 원자적으로 비교합니다. 오래된 상태의 갱신이나 중복 답변은 `SESSION_CONFLICT` 코드와 `409 Conflict`를 반환하여 다른 답변을 덮어쓰지 않도록 합니다. 호출자는 이전 변경 요청을 그대로 재시도하지 않고 현재 상태를 다시 조회한 뒤 새 답변을 제출해야 합니다.

## 퀴즈 흐름

1. **세션 생성** — 아티스트의 후보곡 풀 초기화
2. **질문 조회** — 남은 곡들을 구분할 수 있는 질문 선택
3. **답변 제출** — 후보를 필터링하고 다음 진행 상태 반환
4. **종료 또는 복구** — 매칭 결과와 관련 곡을 보여주거나, 질문 소진 후 마지막 질문 다시 선택

대부분의 질문은 후보를 필터링하지 않는 “모르겠어요”를 제공합니다. 키워드 질문은 별도 건너뛰기 버튼 대신 “목록에 없어요”를 제공하며, 이 선택도 후보를 필터링하지 않고 진행합니다.

### 동적 질문 전략

후보가 줄어들수록 넓은 범위의 필터링에서 정밀한 구분으로 전환합니다. 후보가 적을 때는 가사 힌트와 직접 곡 선택을 활용합니다. 앨범 선택지는 일반 발매와 리패키지를 구분하고, 멤버·솔로곡 관련 규칙으로 후보를 구분하는 데 의미가 없는 질문을 피합니다.

### 답변 결과 상태

| 상태 | 동작 |
|--------|----------|
| `CONTINUE` | 질문 루프 계속 진행 |
| `RESULT` | `finalResult` 안에 매칭된 곡과 관련 곡 추천 반환 |
| `NO_MATCH` | 답변 응답의 `similarSongs` 필드에 추천 반환 |
| `ALL_QUESTIONS_EXHAUSTED` | 추천을 반환하고 마지막 질문을 복구 가능한 상태로 보존 |

답변 응답과 영속 결과 조회 응답은 서로 다른 계약을 가집니다. 다음 질문 조회는 후보가 없거나 질문이 소진되면 여전히 에러를 반환할 수 있으며, 위 복구 가능한 상태는 답변 제출에 해당합니다.

### 마지막 질문 다시 열기

질문 소진 후 `POST /api/v1/sessions/reopen-last-question`은 마지막 답변을 취소하고 재선택할 질문을 반환합니다. 후보 풀과 파생 필터링 상태도 해당 답변 이전 상태로 복원합니다. 다시 열 질문이 없으면 세션 충돌을 반환합니다. 사용자는 매칭 실패 결과로 진행할 수도 있습니다.

### 결과 보강과 공유

곡이 매칭되면 지원되는 건너뛴 질문에 해당 곡의 실제 값을 채웁니다. 결과 화면에서 사용자가 몰랐던 답도 확인할 수 있습니다.

`GET /api/v1/results/{sessionKey}`는 Redis 만료 후에도 영속 결과를 조회합니다. 저장된 곡을 기준으로 추천을 다시 계산할 수 있지만, 답변 이력은 세션이 살아 있는 동안만 제공합니다.

## 결과 일관성

결과 생성은 데이터베이스 트랜잭션 안에서 세션별로 직렬화합니다. 부분 고유 인덱스로 세션당 활성 결과 하나만 허용합니다. 최종 결과·매칭 실패 생성 요청이 반복되거나 동시에 도착해도 첫 활성 결과를 유지하여 곡 연결과 생성 알림의 중복을 방지합니다.

---

## 응답과 보안 경계

- 성공 응답은 표준 HTTP 성공 코드와 함께 데이터를 직접 반환
- 에러는 충돌·만료를 포함한 구조화된 코드와 메시지로 반환
- Worker API 라우트가 백엔드 요청에 공유 시크릿 첨부
- 퀴즈와 공유 결과 엔드포인트는 사용자 로그인 없이 세션 키 사용
- JWT는 사용하는 경로에서 인증 컨텍스트·테넌트 클레임을 전달하며, 브라우저 퀴즈 흐름의 필수 조건은 아님
- 분산 rate limiting으로 세션별 요청 제어

## 멀티테넌시

각 아티스트는 독립된 데이터베이스 스키마를 사용합니다. 인증 컨텍스트, 활성 세션 데이터, 만료된 공유 링크를 위한 영속 세션-테넌트 매핑에서 테넌트를 해석합니다. 커넥션 라우팅 전에 식별자를 검증하며, 재사용 전에 커넥션을 초기화합니다.
