# 백엔드 기술 스택

## 핵심 프레임워크

| 기술 | 비고 |
|-----------|------|
| Kotlin 2.4 | 주 언어 |
| Java 21 | 툴체인 |
| Spring Boot 4.1 | Web, Data JPA, Security, Data Redis, Mustache (어드민) |
| Gradle (Kotlin DSL) | 빌드 시스템 |

---

## 직렬화 호환성

Spring Boot 4 전환 후 애플리케이션의 HTTP·Redis 직렬화는 Jackson 3을 사용합니다. Jackson 2는 JSONB 매핑과 JWT 처리에서 이를 요구하는 라이브러리에 한정해 유지합니다. Enum은 기존 API·Redis 세션 형식을 보존하기 위해 `name()` 표현을 유지하며, 두 경계에 대한 호환성 테스트를 둡니다.

---

## 데이터베이스

| 기술 | 역할 |
|-----------|------|
| PostgreSQL | 주 데이터 저장소 (schema-per-tenant) |
| Hibernate (JPA) | ORM — validate 모드 (스키마는 Flyway로 관리) |
| Flyway | 버전 관리 스키마 마이그레이션, 멀티스키마 지원 |
| hypersistence-utils | 복합 데이터 타입을 위한 JSONB 컬럼 타입 매핑 |

### JSONB 활용

리스트형 및 구조화된 필드를 PostgreSQL JSONB 컬럼으로 저장합니다. 단순한 중첩 데이터에 대해 조인 테이블 오버헤드를 회피하면서도 쿼리 가능성을 유지합니다.

### Flyway 전략

공유 스키마와 테넌트별 스키마의 마이그레이션을 분리 관리합니다. 테넌트 스키마 마이그레이션은 애플리케이션 시작 시 각 테넌트에 적용됩니다.

## 세션 & 캐시

| 기술 | 역할 |
|-----------|------|
| Spring Data Redis | TTL 기반 세션 데이터 저장 |
| Redisson | 분산 rate limiting |

세션 상태는 전적으로 Redis에 저장됩니다 — 백엔드에 인메모리 상태가 없으므로 수평 확장이 가능합니다. API 엣지에서는 Redisson 기반 분산 rate limiting을 적용하여 인스턴스 전반에 걸쳐 세션 단위 남용을 제어합니다.

---

## 보안

| 기술 | 역할 |
|-----------|------|
| Spring Security | 무상태 세션, 경로 기반 인증 규칙 |
| JJWT | JWT 토큰 생성 및 검증 |

- Worker의 API 라우트가 백엔드 공유 시크릿을 첨부하며, 브라우저에는 전달하지 않음
- 퀴즈와 공유 결과 요청은 사용자 로그인 없이 세션 키를 사용
- 테넌트 클레임을 포함한 인증 컨텍스트에 JWT 지원이 존재하지만, 브라우저 퀴즈 흐름에서 요청마다 JWT를 발급받지는 않음
- 분산 rate limiting으로 세션 단위 남용 방지

## 곡 유사도 엔진

여러 속성 카테고리를 가중치 기반으로 종합해 가까운 곡을 랭킹으로 산출하는 유사도 엔진을 운영합니다. 답변 제출 시 매칭 실패·질문 소진 상태에 추천을 제공하고, 매칭 성공 결과에도 관련 곡을 포함합니다. 공유 결과 조회는 세션 만료 후에도 저장된 곡을 기준으로 추천을 다시 계산할 수 있습니다. 다음 질문 조회는 후보가 없거나 질문이 소진된 경우 에러를 반환합니다.

## 어드민 UI

`:admin` 모듈은 서버 렌더링 관리 인터페이스(Mustache 템플릿, 로컬 전용)를 제공하며, 모든 도메인 데이터 관리 및 CSV 일괄 가져오기를 지원합니다. 콘텐츠 큐레이션을 위한 Spotify·YouTube 연동을 제공합니다. 붙여넣은 앨범·콘서트 페이지 HTML을 후보 데이터로 추출하고 가져오기 전에 검토할 수 있습니다. 어드민 폼은 CSRF 보호를 유지하고, 로컬 외 프로필에서는 어드민 권한을 요구합니다.
