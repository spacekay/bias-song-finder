# 기술적 의사결정

사용자가 답변을 두 번 누르거나 요청이 겹치거나 기억이 불완전해도 퀴즈 흐름은 일관되게 이어져야 합니다. 프론트엔드, 세션 저장소, 데이터베이스에서 이러한 상황을 처리한 선택을 정리합니다.

## 동시 답변으로부터 진행 상태 보호

두 요청이 같은 퀴즈 상태를 읽고 각각 다음 상태를 계산할 수 있습니다. 단순한 읽기·수정·저장 방식에서는 늦게 저장된 요청이 앞선 답변을 지워버릴 수 있습니다.

Redis 갱신은 버전을 원자적으로 비교하고 세션의 남은 TTL을 보존합니다. 오래된 상태의 저장과 중복 답변은 충돌로 반환합니다. 여러 인스턴스에서도 저장된 진행 상태를 보호하지만, 호출자는 다시 답변하기 전에 현재 상태를 조회해야 합니다. 요청 제한은 트래픽을 줄이는 역할이며 동시성 제어를 대체하지 않습니다.

## 결과 생성의 멱등성 보장

세션 갱신 충돌을 막는 것만으로 관계형 결과의 중복 생성을 막을 수는 없습니다. 최종 결과와 매칭 실패 경로의 요청이 반복되거나 동시에 도착할 수 있습니다.

트랜잭션 범위의 데이터베이스 잠금으로 세션별 생성을 직렬화하고, 부분 고유 인덱스로 활성 결과 하나를 강제합니다. 첫 활성 결과와 기존 곡 연결을 재사용하여 해당 요청에 따른 생성 알림 중복도 방지합니다. 이 보장은 결과 생성에 한정하며, 외부 알림 전반의 정확히 한 번 전달을 보장하는 것은 아닙니다.

## 질문 소진 후 복구

질문이 소진되었다는 것은 앞선 답변이 잘못되었음을 의미할 수도 있습니다. 바로 종료하면 사용자가 이를 고칠 기회가 사라집니다.

엔진은 복구 가능한 마지막 질문을 보존하고, 후보 풀과 파생 필터를 해당 답변 이전 상태로 복원합니다. 사용자는 질문을 다시 열거나 추천과 함께 매칭 실패 결과로 진행할 수 있습니다. 임의의 과거 답변 전체를 편집하게 하지 않으면서 통제된 복구 전이를 제공합니다.

## 프레임워크 전환 중 계약 보존

Spring Boot 4 전환으로 애플리케이션 직렬화를 Jackson 3으로 옮겼습니다. 소스 타입이 같아 보여도 의존성 업그레이드는 저장된 세션 값과 API의 enum 표현을 바꿀 수 있습니다.

HTTP·Redis 매퍼에서 enum 이름 표현을 명시적으로 유지하고 호환성 테스트로 검증합니다. Jackson 2가 필요한 라이브러리는 별도의 의존 경로로 유지합니다. 일시적으로 두 직렬화 의존성을 관리하는 비용을 받아들이고 기존 전송 형식을 보존한 선택입니다.

## 명확한 요청 경계 유지

브라우저의 퀴즈·결과 요청은 동일 출처 Worker API 라우트를 거치며, 서버에서 백엔드 인증 정보를 첨부합니다. 재시도 가능한 조회에는 제한된 재시도를 적용하고, 변경 요청은 기본적으로 재시도하지 않습니다. 시간 초과만으로 서버가 아무 작업도 하지 않았다고 판단할 수 없기 때문입니다.

결과 조회는 저장된 언어 상태의 복원을 기다리고 언어 쿼리를 검증합니다. 아티스트 설정은 공개 여부를 별도로 관리하여 새 아티스트를 준비하는 것만으로 경로가 노출되지 않게 합니다. 공개 아티스트의 실제 선택 가능 여부는 백엔드 상태로 결정합니다.

## 검증과 운영 가시성

구현 레포지토리에는 서비스 테스트, PostgreSQL·Redis 통합 테스트, 프론트엔드 커버리지 기준, lint, 타입 검사, 빌드 검사가 있습니다. 백엔드는 liveness와 분리하여 데이터베이스·Redis·마이그레이션 준비 상태를 readiness 그룹에서 확인합니다. Worker 이벤트는 작업명을 사용해 요청 결과와 지연을 기록하고, CSP 보고는 정제 후 로깅합니다.

이는 구현된 검사·진단 도구에 대한 설명이며, 측정된 지연 개선이나 가동률 보장을 의미하지 않습니다.
